# סוכן תפעול SEO – מכללת איקום / Ecom School

פרויקט תשתית לסוכן AI לתפעול SEO עבור [מכללת איקום](https://www.ecomschool.co.il/) (WordPress + Elementor). הסוכן **אינו** כותב מאמרים בלבד – הוא תומך במחקר, ביקורת (audit), תכנון, כתיבה, אופטימיזציה, הכנת טיוטות וורדפרס, קישור פנימי, ניתוח Search Console, ו-Brand SERP / Reputation SEO. כל התהליך פועל **תחת פיקוח ואישור אנושי מלא** – שום דבר לא מתפרסם חי ללא אישור מפורש.

**כל פלט אסטרטגי, תוכן, דוחות והמלצות הם בעברית** (קוד/הגדרות טכניות באנגלית לפי הצורך). ראו `agent/system_prompt.md`.

## מבנה הפרויקט

```
docs/        אסטרטגיה, כללים ותהליכים – מקור האמת העסקי
agent/       ה"מוח" התפעולי של הסוכן (system prompt, workflows, כללי אישור, בדיקת ציות)
templates/   תבניות מילוי לכל סוג פלט
data/input/  קבצים שהמשתמש מזין (ייצוא GSC/GA, הערות מתחרים, תוכן מהאתר)
data/output/ כל מה שהסוכן מייצר (audits, content_plans, article_drafts, page_optimizations, schema, reports)
scripts/     סקריפטי Python לעיבוד קבצי CSV שהוזנו (ללא חיבור API חי)
```

## מאיפה מתחילים

1. קראו את `docs/00_PROJECT_OVERVIEW.md` – סקירת הפרויקט המלאה.
2. קראו את `agent/system_prompt.md` – זהות הסוכן וכללי הברזל שלו.
3. עיינו ב-`data/output/audits/00_MVP2_STATUS_AND_NEXT_STEPS.md` – תוכנית הפעולה הראשונה ומה נדרש כדי להשלים אותה עם נתונים אמיתיים.

## סטטוס נוכחי (MVP1 + MVP2 ראשוני)

**בנוי ומוכן:**
- שכבת הנחיות מלאה לסוכן (`/agent`), כללי ציות (`docs/02_SEO_RULES_AND_COMPLIANCE.md`), אסטרטגיית מילות מפתח לאשכול הסייבר (`docs/03_KEYWORD_STRATEGY.md`), תהליך וורדפרס (`docs/06_WORDPRESS_WORKFLOW.md`), אסטרטגיית Brand SERP (`docs/08_BRAND_SERP_STRATEGY.md`), מערכת אישורים (`docs/09_APPROVAL_PROCESS.md`), כל 8 התבניות, וכל 5 הסקריפטים (נבדקו ידנית מול נתוני CSV לדוגמה ועובדים כראוי).
- תוכנית פעולה ראשונה (MVP2): ביקורות מבניות לדף הבית ולדפי הקורס בעדיפות, חבילת אופטימיזציה מלאה לדף קורס הסייבר, 10 בריפים למאמרי אשכול הסייבר, 10 עדכוני תוכן, 10 המלצות קישור פנימי, ו-5 נכסי Brand SERP ראשונים.

**מגבלה ידועה בסבב זה:** לא הייתה גישת רשת חיה לאתר `ecomschool.co.il` מתוך סביבת העבודה (חסימת מדיניות ארגונית ברמת הפרוקסי, לא תקלה באתר עצמו). לכן ביקורות ה-MVP2 מבוססות על מבנה נתון (URLs, אסטרטגיה עסקית) ולא על תוכן אמיתי שנשלף מהעמודים. כל מקום שדורש זאת מסומן בבירור "ממתין לנתונים בפועל". פירוט מלא ואיך להשלים: `data/output/audits/00_MVP2_STATUS_AND_NEXT_STEPS.md`.

**לא מחובר בכוונה (כנדרש):**
- אין חיבור API ל-WordPress, ל-Search Console, או ל-Google Analytics.
- אין פרסום אוטומטי – כל תוכן הוא Draft בלבד עד אישור אנושי.
- אין נתוני מחקר מתחרים אמיתיים עדיין (יש מתודולוגיה ותבנית, ממתין לתוכן שיסופק).

## איך להריץ את הסקריפטים

ראו `scripts/README.md` – כל הסקריפטים הם Python 3 סטנדרטי (ללא תלויות חיצוניות) ופועלים על קובצי CSV שהורדתם/ייצאתם ידנית ל-`data/input/`.

## עקרונות יסוד (לא לחרוג מהם)

1. תוכן קיים נבדק **לפני** יצירת תוכן חדש.
2. עמוד יעד אחד בלבד לכל מילת מפתח (אין קניבליזציה).
3. אין הבטחת עבודה/השמה/שכר/דירוג – ראו `docs/02_SEO_RULES_AND_COMPLIANCE.md`.
4. אין נתונים מומצאים – חוסר מידע מסומן בפירוש, לא מנוחש.
5. כל פרסום עובר דרך מערכת האישורים (`docs/09_APPROVAL_PROCESS.md`).
