# 06 – תהליך עבודה מול WordPress

## כלל הברזל

הסוכן **לעולם לא מפרסם תוכן חי**. כל תוכן שנוצר עבור וורדפרס נשמר כטיוטה (Draft) או ל"ממתין לבדיקה" (Pending Review) בלבד. פרסום בפועל הוא פעולה אנושית מודעת, לאחר אישור מפורש (ראו `09_APPROVAL_PROCESS.md`).

## מצב חיבור נוכחי

**אין כרגע פרטי גישה ל-WordPress API** (לא REST API, לא Application Passwords, לא תוסף). לכן, בשלב זה, הסוכן פועל ב**מצב קובץ מוכן להעתקה**:

1. הסוכן מייצר קובץ טיוטה מלא (Markdown + HTML נקי) לפי `templates/wordpress_draft_template.md`.
2. הקובץ נשמר תחת `data/output/article_drafts/` או `data/output/page_optimizations/`.
3. מצורפות הוראות העתקה ידנית לעורך וורדפרס/Elementor.
4. כאשר יסופקו פרטי גישה (בעתיד, ורק כשהמשתמש יבקש זאת במפורש), ניתן יהיה לשדרג לפרסום Draft אוטומטי דרך ה-REST API של וורדפרס – **לא לפני כן**.

## כללי בטיחות ל-Elementor

- הסוכן **לא** נוגע במבנה ה-JSON הפנימי של Elementor (`_elementor_data`) ולא מנסה לערוך אותו ישירות.
- כאשר מעדכנים עמוד קיים שנבנה ב-Elementor, הסוכן מספק **טקסט מוכן להדבקה בתוך הווידג'טים הקיימים** (כותרות, פסקאות, כפתורי CTA, שאלות נפוצות) – לא מבנה עמוד חדש.
- עבור מאמרי בלוג חדשים (בדרך כלל לא בנויים ב-Elementor אלא בעורך הבלוקים הרגיל) – ניתן לספק HTML נקי ומוכן להדבקה.
- אם עמוד קיים דורש שינוי מבני (הוספת סקשן חדש), הסוכן מציין זאת בפירוש כ"נדרשת עריכה ידנית במבנה העמוד" ומספק את התוכן הטקסטואלי + תיאור מיקום מומלץ – לא קוד Elementor.
- **לעולם לא לשבור עמוד קיים.** בעדכון עמוד, תמיד יש לצרף גרסת "לפני" ו"אחרי" לצורך השוואה.

## סוגי פעולות נתמכות

1. **יצירת טיוטת פוסט בלוג חדש** – כותרת, תוכן מלא, מטא-דאטה SEO, תמונה מומלצת + alt, קטגוריה/תגיות מוצעות.
2. **עדכון טיוטת פוסט קיים** – מוצג diff ברור בין הגרסה הקיימת למוצעת.
3. **הכנת עדכון תוכן לעמוד קיים** (כמו דף קורס) – בלוקים טקסטואליים בלבד, לפי מיקום בעמוד.
4. **הכנת שדות מטא-דאטה SEO** – ראו נספח תוספי SEO למטה.
5. **הכנת בלוקי טקסט "בטוחים ל-Elementor"** – טקסט נקי ללא תגיות HTML מיותרות, מוכן להדבקה בווידג'ט טקסט/כותרת.
6. **יצירת HTML** – רק כאשר רלוונטי (למשל טבלת FAQ מובנית, או קוד JSON-LD להטמעה).

## נספח: מיפוי שדות לתוספי SEO נפוצים

**לא ידוע כרגע אילו תוסף SEO מותקן באתר בפועל (Yoast / RankMath / אחר) — יש לאמת ולעדכן נספח זה.** עד לאימות, הטיוטות כוללות את שני השדות הגנריים "כותרת SEO" ו-"תיאור מטא" שמתאימים לכל תוסף, ובנוסף המיפוי הספציפי הבא:

| שדה גנרי | Yoast SEO | RankMath |
|---|---|---|
| כותרת SEO | SEO title | Title |
| תיאור מטא | Meta description | Description |
| מילת מפתח יעד | Focus keyphrase | Focus Keyword |
| Schema מותאם | Yoast Schema (FAQ/How-to blocks) | RankMath Schema Generator |
| Breadcrumb | Yoast Breadcrumbs | RankMath Breadcrumbs |
| Canonical | Advanced → Canonical URL | Advanced → Canonical URL |

## תהליך העבודה בפועל (מצב נוכחי, ללא API)

```
1. הסוכן מכין קובץ טיוטה מלא לפי templates/wordpress_draft_template.md
2. הקובץ מסומן בסטטוס "Ready for WordPress draft" (ראו 09_APPROVAL_PROCESS.md)
3. המשתמש (או חבר צוות) מעתיק את התוכן ידנית לעורך הוורדפרס, שומר כ-Draft
4. המשתמש מסמן בחזרה בפרויקט שהטיוטה "הועלתה לוורדפרס כטיוטה"
5. רק לאחר בדיקה ואישור בוורדפרס עצמו – פרסום ידני על ידי המשתמש
```

## עתיד (לא כעת)

כאשר המשתמש יספק Application Password / REST API credentials לוורדפרס, ניתן יהיה להוסיף שלב אוטומטי שיוצר את הטיוטה ישירות בוורדפרס במצב `draft` או `pending` (לעולם לא `publish` אוטומטית). זה ידרוש עדכון למסמך זה ואישור מפורש נפרד מהמשתמש לפני חיבור בפועל.

**התוכנית המלאה לשלב הזה כבר קיימת** (תכנון בלבד, טרם מוטמע, טרם מחובר): `../SAFE_INTEGRATION_PLAN.md` ו-`../integration/01_wordpress_draft_creation_plan.md`. התוכנית מבוססת על משתמש וורדפרס ייעודי בתפקיד Contributor (חסום ברמת השרת מלפרסם ומלערוך עמודים) ועל שער אישור נפרד (`../integration/04_approval_gate_plan.md`, `../data/approval/`) לפני כל יצירת טיוטה.
